# Сервис коротких ссылок

Консольная программа на Java 21. Создаёт короткие ссылки с ограничением по времени и числу переходов.

## Запуск

Из папки проекта выполните:

```bash
sh scripts/run.sh
```

Для создания первой ссылки введите, например:

```text
new https://example.org 2
```

Программа покажет ваш UUID и короткую ссылку. UUID сохраняется автоматически для следующих запусков. Вместо `2` можно указать другой лимит или не указывать его вовсе. Чтобы открыть исходный сайт, введите `open` и полученный код, например `open Ab3x9Q2k`. Короткая ссылка используется **в консоли**, а не в адресной строке браузера.

## Команды

| Команда | Что делает |
| --- | --- |
| `help` | Показать подсказку |
| `new <URL> [лимит]` | Создать короткую ссылку |
| `open <код>` | Открыть сайт по короткой ссылке |
| `list` | Показать свои ссылки и число переходов |
| `limit <код> <число>` | Изменить лимит своей ссылки |
| `edit <код> <URL>` | Изменить адрес своей ссылки |
| `delete <код>` | Удалить свою ссылку |
| `user <UUID>` | Выбрать пользователя |
| `cleanup` | Удалить просроченные ссылки вручную |
| `exit` | Выйти |

Ссылка перестаёт открываться после исчерпания лимита или истечения срока действия. При необходимости создайте новую.

## Как устроен проект

- `Main.java` — консольный интерфейс: читает команды, показывает результаты и открывает URL в браузере.
- `LinkService.java` и `ShortLink.java` — основная логика: генерация уникального кода, UUID владельца, лимит переходов, TTL, проверки прав и уведомления.
- `FileLinkStore.java` — сохранение ссылок в `data/links.tsv`; `Config.java` — чтение параметров из `config.properties`.

Зависимости передаются в `LinkService` через простые интерфейсы хранилища и браузера. Поэтому бизнес-логику можно тестировать без файловой системы и без запуска браузера. В приложении используется файловое хранилище, а фоновой задачей раз в заданный интервал удаляются истёкшие ссылки.

## Тесты

Выйдите из программы и выполните из папки проекта:

```bash
sh scripts/test.sh
```

Успешный результат: `Пройдено тестов: 23`.

Тесты проверяют и отдельные правила сервиса (URL, лимит, UUID, права, TTL), и интеграционные сценарии с файловым хранилищем (сохранение и загрузка после перезапуска). В `.github/workflows/ci.yml` этот же скрипт запускается автоматически при каждом push и pull request.
